READING EXAMPLE

跟着一次“读文件并总结”走完流程

以下是帮助理解的示例路径，不是实测输出，也不保证模型一定调用工具。假设 read 工具已启用、文件可读，且没有扩展拦截、错误、插话或压缩。

  1. 用户输入

    “读取 README.md 并总结。”经过输入分流后，组装为 role: user 消息。

    查看消息组装 →
  2. 第一次模型响应

    运行时消息转换为模型消息。假设模型返回一个 toolCall：名称 read，参数指向 README.md。

    查看响应消息 →
  3. 执行与回传

    校验参数、检查工具钩子，然后执行 read。结果形成 role: toolResult，通过 toolCallId 对应这次调用。

    查看工具执行 →
  4. 下一次模型响应

    把工具结果加入上下文，进行下一轮准备，再请求模型生成总结。工具输出和最终总结是两条不同的消息。

    查看轮间准备 →
  5. 结束与保存

    若无工具调用、后续队列或停止钩子的额外处理，核心循环结束；Session 继续做收尾检查。消息在各自的 message_end 时追加会话条目，并按持久化条件写文件。

    查看事件与保存 →

对应源码见下方“输入”“一轮结束后的判断顺序”和“持久化”。

GLOSSARY

几个词，分清再读

entry / 条目
会话树中的一条记录；它可以是消息、压缩摘要或设置变化。
parentId / leafId
parentId 指向父条目；leafId 表示当前分支的位置。恢复时沿所选叶节点的路径取上下文。
turn / 一轮
一次 assistant 响应及其对应的工具处理。一个 run 可以包含多轮。
run / 一次运行
一次核心循环调用；Session 为重试或排队消息继续调用时，同一次用户交互可能跨多个 run。
toolCall / toolResult
前者是 assistant 请求执行工具的内容块；后者是工具执行反馈消息，用 toolCallId 关联。
压缩
以摘要替代当前上下文的一部分历史；会话文件中的旧条目保留。
