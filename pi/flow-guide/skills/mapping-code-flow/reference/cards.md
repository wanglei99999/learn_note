# 写详解卡

## 两层知识

- **步骤卡**（`## 各步详解` 下，`### 站名` 或 `### 站名 · 步骤名`）：这一步整体在做什么、涉及哪几个节点、为什么这样设计、通用模式。
- **节点卡**（`## 节点详解` 下，`### 节点ID：显示名`）：具体函数、数据、钩子。**每个节点都要有**，同一个节点出现在好几步里时只写一次。

两层不重复：步骤卡讲"这几个东西怎么配合、为什么"，节点卡讲"这个东西具体长什么样、有什么坑"。

## 小标题词表

卡内用 `####` 分块，只用下面这些名字（查看页按名字配色）：

| 小标题 | 写什么 | 常用在 |
|---|---|---|
| 关键源码 | 5 到 15 行原文摘录，先说明它在哪、干什么 | 普通节点 |
| 数据实例 | 这个数据真实的样子（JSON / 对象字面量 / 原始报文） | 数据节点、存储节点 |
| 设计理由 | 为什么这样做，写成结论 | 步骤卡 |
| 容易误解 | 边界、坑、和直觉不符的行为 | 所有节点 |
| 代价 | 这个设计带来的负担 | 步骤卡、关键节点 |
| 谁在读写 | 表格：字段 / 什么时候写 / 位置 | 状态、存储节点 |
| 扩展能做什么 | 这个钩子能干什么，对应仓库里的示例 | 钩子节点 |
| 通用模式 | 这个做法的通用名字，读别的项目时该找什么 | 步骤卡 |

每张卡挑 2 到 4 块，不求填满。卡片开头可以先写一段不带小标题的概述。

## 写作规则

1. **先读源码再写**。每条论断都要能落到一行代码或一条源码注释上。
2. **写结论，不出题**。这是参考资料，不是练习册。
3. **"为了……"只写能证明的**：源码注释写了，或者行为本身能说明。说不清意图时，只写效果。
4. **代码是原文**。删过行、合并过写法，就在说明里写"有简化"；用 `…` 表示省略。
5. **编的数据标"示意"**：id、时间戳、token 数这类。
6. **示例扩展要真的存在**。仓库里没有对应示例，就写"典型用法"，不要编文件名。
7. 中文、短句、直接说。发布前可以用 qu-ai-wei 技能去一遍 AI 腔。

## 引用和跳转

- 源码引用：正文里写 `[agent.ts:437]`（文件名 + 行号）或 `[examples/foo.ts]`（整个文件）。文件名写成能唯一定位的最短路径后缀；想用更短的名字，在 md 里加 `<!-- sources {…} -->` 别名。链接定义由 `link-refs.mjs` 生成，不要手写。
- 卡片跳转：`[agent.state](#node:STATE)`，查看页里点了打开那个节点的卡。

## 核对

1. `node link-refs.mjs <md> --repo <源码目录>`：把每条引用指向的行打印出来，**逐条看**。打印出空行、单独的括号、和正文说法对不上的，都要改行号。行号差一两行是最常见的错误。
2. 没有问题后加 `--write` 写入链接定义。
3. `make-viewer.mjs` 最后会列出还没有卡的步骤和节点，目标是"每一步、每个节点都有卡"。
4. 在浏览器里把每张卡打开一遍，确认没有空卡、控制台没有报错。
