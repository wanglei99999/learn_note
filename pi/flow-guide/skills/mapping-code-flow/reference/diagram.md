# 画图和配导览

## 先定范围

- **一个具体场景**：一条输入从哪进、到哪落地。比如"一条消息从回车到写进会话文件，再回到屏幕"。场景越具体，图越能画准。
- **一种模式**：多种前端或运行模式共用核心时，只画一种，在开头写明不画哪些。
- **钉住版本**：记下 commit，所有 `文件:行号` 都按这个版本。发布用的链接要指向远程上存在的提交。

范围不清楚时先问用户，别自己扩大。

## 分站

- 按**数据路径**分站，不按代码目录。每站一个编号（⓪ ① ② …），从上往下读。
- 启动时只走一次的（加载、装配）单独成站，放在最上面。
- 每站画成一个 `subgraph`，标题写"编号 名字 · 主要文件"。

## 节点

| 形状 | mermaid 写法 | 用在 | classDef |
|---|---|---|---|
| 矩形 | `ID["…"]` | 普通步骤、函数 | 不加 |
| 六边形 | `ID{{"…"}}` | 扩展点 / 钩子 | `hook` |
| 平行四边形 | `ID[/"…"/]` | 数据在这一站的形状 | `data` |
| 圆柱 | `ID[("…")]` | 状态、存储 | `store` |
| 菱形 | `ID{"…"}` | 分支判断 | 不加或 `check` |
| 体育场 | `ID(["…"])` | 事件、起止 | 不加 |

- classDef 用固定的五个名字和颜色（模板里有），查看页的图例按这五个名字配色。图例上的文字在导览配置的 `legend` 里改。
- 节点 id 用大写短词（`SNAP`、`HCTX`），节点卡靠它对应。
- 标签格式：`函数名 · 文件:行号<br/>一句话说它做什么`。同一站里文件相同时，行号可以只写 `:1234`。
- 数据节点只写形状（字段名），不写长篇解释；解释放节点卡。

## 布局技巧

ELK 分层布局遇到回边会乱，按下面处理：

1. **循环只展开一次**：把循环体按顺序画出来，只留一条"回到 ④"的回边，并把它写进 `loopBack`（追踪路径时不走回边）。
2. **状态和存储画两次**：上面一个接启动时写入和读取，下面一个接运行中的写回，标签注明"和上面是同一个"。
3. **长回边改成文字**：跨好几站往回指的线，删掉，在节点标签里写"之后回到 ③"。
4. 实线表示主路径，虚线（`-.->`）表示读写状态、跨阶段的关系。

## 导览配置

写在图后面的 HTML 注释里，是 JSON：

```json
{
  "title": "查看页标题（不写就取一级标题冒号前的部分）",
  "legend": { "hook": "扩展钩子", "check": "压缩检查点", "world": null },
  "loopBack": ["NEXT>INJ"],
  "stations": [
    { "label": "① 输入", "view": ["HUMAN", "S0"], "desc": "一两句话" },
    { "label": "② prompt", "view": ["PROMPT", "S1"], "desc": "这一站的概述", "shots": [
      { "title": "分流", "view": ["CMD", "HIN", "EXP"], "desc": "这一步的说明" }
    ] }
  ]
}
```

- `view` 里可以写 subgraph id（整组）或节点 id。站级 `view` 决定这一站的范围（分组框会点亮）；`shots` 里的 `view` 是每一步镜头对准的节点。
- `legend` 的键：step、hook、data、store、check、world、decision、event、solid、dashed、up、down；值写 `null` 表示不显示。
- **分步标准**：每一步在 1600×717 的窗口里缩放不低于 75%（节点总高约 800 像素以内）。大站拆成 3 到 4 步。
- 一步里要把"出口"的下一个节点也包含进来，读者能看到这一步流向哪。
