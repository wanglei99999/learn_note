# 代码全流程图解

## 概述

产出两个文件：一个 markdown（mermaid 全流程图 + 导览配置 + 步骤卡 + 节点卡），和由它生成的一个独立 html 查看页。查看页能按站分步走、点节点看上下游、按需展开详解卡。

核心原则：**只依据源码**。图上每个节点、卡里每条论断都要能落到某个版本的某一行代码；不参照笔记、博客这类二手材料。

## 什么时候用

- 想把一个系统的执行链路串起来，而不是零散地看函数。
- 准备讲解、写 blog、面试前梳理架构，需要一份能发布的图解。

不适用：只想了解目录和模块划分（用 learn-project）；只看一个函数。

## 工具

工具在本 skill 目录的 `tools/` 下，第一次用先在那里跑 `npm install --ignore-scripts`。

| 命令（在 tools/ 下） | 作用 |
|---|---|
| `node check.mjs <md>` | 检查 mermaid 语法 |
| `node link-refs.mjs <md> --repo <源码目录>` | 打印每条源码引用指向的那一行，供核对；加 `--write` 写入固定到当前提交的链接 |
| `node make-viewer.mjs <md> <html>` | 生成查看页，并列出还没有卡的步骤和节点 |

起步模板：`templates/flow-map.md`，复制到用户的笔记目录再改。查看页打开时要联网（从 jsDelivr 加载 mermaid）。

## 流程

1. **定范围**：一个具体场景、一种运行模式、一个 commit。和用户确认，写进 md 开头。
2. **读源码，画骨架**：按数据路径分站，节点标签带 `文件:行号`。画法见 `reference/diagram.md`。
3. **配导览**：分站、大站拆步、标出循环回边。每一步在 1600×717 的窗口里缩放不低于 75%。
4. **写卡**：每一步一张步骤卡，每个节点一张节点卡。写法见 `reference/cards.md`。
5. **核对**：`link-refs.mjs` 打印的每一行都看一遍，改掉对不上的行号，再 `--write`。
6. **生成并验证**：`check.mjs` → `make-viewer.mjs` → 浏览器里检查（见下方清单）。

## 规则

- 画图、写卡都只看源码。发现图和源码不符，改图，并告诉用户改了哪里。
- 没核实的"为了……"不写；编的数值标"示意"；改过的代码标"有简化"。
- 详解默认收起，靠按钮打开：左栏"展开详解"开步骤卡；点节点先出上下游小面板，再点"展开详解"开节点卡。不要点节点直接出卡。
- 某种标记如果每个元素都有，就不加（每个节点都有卡，所以图上不标"有卡"）。
- 提交、推送、装到系统目录，都等用户明确同意。

## 验证清单

- `make-viewer.mjs` 输出"每一步、每个节点都有卡"。
- 逐步点"下一步"：每步缩放 ≥ 75%，这一步的节点全在画面里；打开步骤卡后节点不被卡片挡住。
- 每张卡都能打开、有内容；卡片之间的 `#node:` 跳转可用。
- 控制台没有报错。
- 用浏览器自动化截图卡住时，多半是窗口被遮挡、浏览器暂停了渲染：改用脚本读 DOM 和坐标来检查。

## 常见错误

| 现象 | 原因 | 做法 |
|---|---|---|
| 整张图缩下来字小到读不了 | 一站里节点太多 | 大站拆成几步，每步 ≥ 75% |
| 布局乱、某站被甩到最底下 | 回边和写回的线太多 | 循环只展开一次；存储画两次；长回边改文字 |
| 同一个节点的知识写了好几遍 | 知识挂在步骤上 | 具体知识挂节点，步骤卡只讲整体 |
| 行号差一两行 | 凭记忆写，没回查 | 用 `link-refs.mjs` 打印核对 |
| 短文件名链接到错的文件 | 仓库里有重名文件 | 写更长的路径后缀，或加 `sources` 别名 |
| 卡片里的 `## 标题` 被当成新章节 | 代码块里有 markdown 标题 | 工具已按行跳过代码块，别在代码块外写多余的 `##` |
