# 内容模型与维护

在新建内容来源或合并多套说明时使用。以下是字段关系示意，不是必须实现的框架，也不是可直接运行的生成器。

## 最小关系

| 对象 | 建议字段 | 约束 |
|---|---|---|
| 源码基准 | revision、checkedAt、workspaceChanges、scope | 区分提交内容与工作区改动 |
| 引用 | id、path、symbol、line、revision | 用完整仓库相对路径定位 |
| 节点 | id、title、kind、summary、detail、sourceRefs、topicRefs | 稳定 id 独立于标签与排列位置 |
| 边 | from、to、relation、condition、sourceRefs | relation 区分调用、数据、事件、状态读写与循环 |
| 阶段 | id、title、purpose、stepIds | 按执行职责而非目录机械分组 |
| 步骤 | id、stageId、title、input、output、nodeIds、branches | 范围应适合一次阅读 |
| 主题 | id、title、body、sourceRefs | 共享说明只维护一次 |

只有明确需要筛选“已核验／待核验”时才增加核验状态字段。不要为一次小修改引入数据库、构建系统或复杂内容管理平台。

## 内容示意

```yaml
node:
  id: restore-context
  title: 恢复当前上下文
  kind: transform
  summary: 从选定历史分支构造运行时消息。
  sourceRefs: [restore-function]
  topicRefs: [history-and-runtime]
step:
  id: restore-session
  input: 会话条目与选定分支位置
  output: 运行时上下文
  nodeIds: [restore-context]
```

这个示意不表示任何具体仓库行为；真实字段含义与判断条件必须回查目标源码。渲染器从引用生成源码链接，从主题标识生成说明入口。搜索也读取这份模型，不另抄节点名称。

## 迁移已有页面

1. 找出手工源、生成文件、运行时转换层和历史快照，记录当前入口。
2. 在修改前保存所需快照；提取节点、边、步骤及引用关系作为对照。
3. 选择保留的权威来源；按主题或阶段合并重复说明，不一次迁移所有不相关资料。
4. 用显式字段修改含义，不依赖旧文案的字面匹配。更新视图，使它们读取同一内容模型。
5. 比较迁移前后标识和连线。语义修改需单列，不能被包装成纯技术迁移。
6. 检查源内容重新生成页面后仍含全部修正；验证旧备份没有依赖新模型。

若暂时不能消除转换层，应明确它的覆盖范围，并设置后续合并位置；不要把临时补丁宣布为长期单一来源。

## 核验记录

记录“论断 → 源码证据 → 核验范围”，例如：

| 论断 | 应读证据 | 常见误判 |
|---|---|---|
| 快照隔离修改 | 拷贝函数与后续对象写入 | 新数组被当作深拷贝 |
| 操作结束 | 完成事件、监听者等待、状态清理 | 收到结束事件等于系统空闲 |
| 内容已落盘 | 条目追加与持久化分支 | 加入内存列表等于写入文件 |
| 请求会继续 | 分支顺序、停止条件、队列 | 正常路径被写成无条件规则 |

最终报告注明核验了新增内容、选定主题还是全部资料。自动检查引用路径和行号的结果，与人工理解对应实现的结果分别报告。
