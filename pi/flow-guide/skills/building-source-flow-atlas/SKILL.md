# 源码流程学习导览

把一个具体场景的执行路径整理成可沿图阅读、可回查源码、可维护的学习资料。目标是让读者知道谁调用当前节点、数据如何变化、下一步交给谁；不是画出代码库的全部函数。

这是方法型技能，不附带页面生成器。按项目现有技术实现，不要求使用某个图形库、单页框架或固定文件名。

## 先判断本次工作

- 新建导览：明确入口、运行模式、主路径和源码版本；先完成一条能走通的最小路径，再补分支。
- 改进已有导览：先检查现有内容来源、生成流程和页面入口。保留已授权的范围，只修改需要改进的内容或交互。
- 核验资料：区分新增内容核验和全量审计；不能把抽查结果描述成全量正确。
- 仅讨论方案：给出判断与取舍，不修改文件。已有明确实施授权时，不重复索要同一授权。

范围可以从对话推断时直接说明采用的范围。缺失信息会改变执行路径时再询问，例如 CLI 与服务端入口不同、提供商协议不同。

## 源码证据先于解释

记录提交标识与核对日期，并检查相关源码是否有未提交修改。若有，说明依据的是工作区快照；不能让固定提交链接假装包含这些修改。

沿调用关系阅读相关函数及其调用者、被调用者、事件订阅和状态更新点。搜索结果用于定位，不用于替代控制流检查。重点核对：

- 输入输出的实际类型，内存数据、持久化记录与外部请求之间的转换。
- 引用、浅拷贝、深拷贝，以及对象更新和数组替换的区别。
- await、队列和回调发生的顺序；通知、运行结束和系统空闲是否为不同时间点。
- 正常路径以外的提前返回、取消、错误、重试、截断和停止条件。
- 默认设置与可配置行为；公共机制与某个适配器的实现细节。

每条关键论断关联完整仓库路径、符号和源码位置。链接固定到核对提交，避免只用容易重名的文件名。

核验分两层：文件、符号、行号存在是结构核验；对应代码确实支持这句话是语义核验。脚本通过只能证明它实际检查的部分。

设计动机只有在代码、测试或维护者说明支持时才作为事实写出。自己的解释标为推断；演示数据标为示例，不能称为实测结果。未经核验的旧说明不因被新版页面引用就变成已核验内容。

## 内容分层与去重

| 层次 | 应回答什么 | 不放什么 |
|---|---|---|
| 阶段总览 | 这一段负责什么，与前后阶段如何连接 | 长源码与完整术语解释 |
| 阅读步骤 | 本步输入、输出、执行顺序及分支条件 | 每个函数的所有实现细节 |
| 节点详解 | 调用者、数据变化、关键逻辑、源码证据 | 多处复制同一套背景知识 |
| 共通知识 | 多阶段共享的概念、示例或易混淆边界 | 脱离当前场景的百科内容 |

共通知识只维护一份，相关步骤或节点给一句上下文提示并链接过去。只有确实需要跨步骤理解时才新增说明页；用户不需要额外笔记时，不主动扩充成全项目课程。

图是有范围的简化表达。省略的条件会影响读者判断时，应在节点或边旁提示并链接详解，不让“主路径”看起来像无条件成立的规则。

## 一份内容，多种视图

将节点、边、阶段、步骤、说明和源码引用作为共同的内容模型。视图负责布局与交互，不各自维护事实文本。

选择 Markdown 加结构化配置，或其他适合项目的可读格式；不强制格式。建立或迁移模型时读 [内容模型与维护](references/content-model.md)。

避免长期通过字符串替换修补图标签，或将相同补充段落注入许多卡片。迁移已有系统时先保留稳定标识和引用关系，逐步合并成一份权威内容。不要直接覆盖生成页面却让源文件停留在旧版。

## 根据阅读任务选择视图

需要时提供阶段总览、逐步阅读和完整大图，不以凑齐三种视图为目标。

- 总览用于找阶段；卡片展示职责或输入输出，提供明确的深入入口。
- 逐步阅读用于理解局部；流程和详情可并排，窄屏按阅读顺序排列。
- 完整大图用于看关联；选择节点、追踪路径和阅读长说明应有清晰入口，避免一次点击同时触发多件意外动作。

统一语义配色：底色表示节点类别，描边表示选择，上下游以颜色与线型共同区分。提供图例，不让颜色同时承担类别、错误、进度等冲突含义。形状与含义一致，例如存储圆柱不用于外部 API。

文字实际可读比固定缩放比例更重要。在目标窗口和详情展开状态下检查字号、遮挡和留白；优先缩小每步范围、拆分步骤或允许滚动，避免一味缩小整图。

导航区分两种意图：主动“定位本阶段”移动镜头；普通切换视图保留镜头和阅读位置。提供适应画布、回到当前步骤、返回阅读位置等与任务相符的操作。

深链接使用稳定的阶段、步骤或节点标识。验证刷新、后退前进和无效参数回退。嵌入画布异步加载时，要处理就绪通知和待执行定位；跨窗口消息校验来源、发送窗口和参数。

## 修改前保存可比对的状态

用户要求备份或准备进行较大重构时，先保存页面、内容与所需资源的独立快照，再修改。已有快照不覆盖；校验文件哈希并记录版本和入口。

备份中的相对路径、脚本、样式和 iframe 也要指向备份资源。只复制一个 HTML，而让它继续读取最新数据，不是可用于历史对比的完整备份。保留外部依赖时说明联网条件，不把它称作离线自包含。

整理文件优先明确当前入口、历史快照和制作技能的区别；实际搬移时更新引用并验证旧链接的处理方式。遵循用户已表达的整理偏好。

## 交付前验证

按改动范围选取检查；不要用样式字符串匹配测试冒充行为验证。

- 内容：节点和边无意外丢失，步骤指向有效节点，引用和共通知识链接可解析；图与详情表达一致。
- 语义：逐条检查本次修改的事实与分支。全量审计另需覆盖旧内容，并列明尚未核验的部分。
- 交互：代表性步骤、跨阶段跳转、选择与取消、路径追踪、详情开合和浏览器历史。
- 状态：主动定位正确，普通切换不重置缩放、镜头、选中项或阅读滚动位置。
- 布局：目标桌面尺寸、详情展开、需要支持的窄屏，检查真实可读性与焦点可达性。
- 交付：旧版能独立打开，当前入口明确；浏览器加载新资源，避免缓存旧脚本造成误判。

使用当前环境支持的浏览器工具并遵循其操作规范。异常先区分资源缓存、渲染未就绪、动画未结束和真实逻辑错误，再修改实现。

完成时报告改了什么、源码基准、核验范围、验证结果和备份入口。仓库其他检查失败时如实说明影响，不能把未通过的检查宣称通过，也不顺手修改无关源码。

## 方法的边界

流程导览帮助读者沿一条执行链进入源码，不等同于整个项目的架构教材。已有资料足以支撑阅读时，应建议实际走读与修正，而非持续堆叠页面和功能。
