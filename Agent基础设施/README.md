# Agent 基础设施

服务端 agent 运行时的原理笔记，是 [Agent](../Agent/README.md) 系列的下一层。Agent 系列讲一个 agent 内部的 harness 怎么构成；这个系列讲把 agent 放到服务端之后，harness 之外还需要什么：会话怎样比进程活得久，沙箱怎样隔离和恢复，两边的状态在崩溃、断线、回收之后怎样重新一致。

笔记以 pi 1.3.0 的 `pi-durable`、`pi-env` 为主要分析对象，配合 E2B、CubeSandbox、Replit、Fly.io、Modal、gVisor、Firecracker 的公开资料。所有选择最后都落到 [Tether](https://github.com/wanglei99999/tether) 的设计上。构造的例子和数字都标明"示意"，可以手算核对；引用的性能数据注明出处，没有实测的不给数字。

| 顺序 | 笔记 | 核心内容 |
|------|------|---------|
| 1 | [服务端 agent 运行时](01-服务端agent运行时.md) | 会话、执行环境、客户端三份状态；三种不一致与对应的机制；不一致而无法修复时写一条模型可见的说明；一致性由注入故障的测试证明 |
| 2 | [harness 的位置](02-harness的位置.md) | 进沙箱与不进沙箱两种布局；凭据、会话状态、资源占用三条边界；每次工具调用跨进程的代价；适合进沙箱的三种场景 |
| 3 | [执行通道](03-执行通道.md) | `ExecutionEnv` 接口与客户端、daemon 的分工；同步行与帧格式；回复优先于输出、输出窗口与溢出文件；心跳与两个退出条件；句柄属于 daemon，在途写操作结果未知 |
| 4 | [持久化执行](04-持久化执行.md) | 先提交再展示；条目、文档、任务；意图先于执行；重放策略与至多一次；replay-safe 不等于幂等；嵌套调用与 code mode 的确定性重放；requestId 与忙碌时的输入；错误的三条边界 |
| 5 | [崩溃后的旧进程](05-崩溃后的旧进程.md) | 两个所有者同时写工作区；窗口来自连接卡住而非断开；与 fencing token 的对照；epoch 与启动命令函数的插入点；每个命令单独开会话，用 `kill -1` 清理；PID 命名空间的防护；实测窗口约 30 秒、隔离 264 ms |
| 6 | [沙箱检查点](06-沙箱检查点.md) | 对话能回到过去，文件系统不能；镜像层、文件层、文件系统层、块设备层、应用层五种做法；docker commit 的累积重复；overlay 分层为什么不可用；reflink 与 CubeCoW；内存快照的匿名页与 soft-dirty；四种做法的实测对比 |
| 7 | [沙箱后端](07-沙箱后端.md) | 沙箱代码与宿主内核之间隔着什么；容器的四层机制；gVisor 的 Sentry 与 systrap；Firecracker 的最小设备模型；隔离强度、开销、快照能力与硬件要求的对比 |
| 8 | [运行边界与自定义条目](08-运行边界与自定义条目.md) | 钩子按模型回合触发；`LiveDoc.run` 里描述此刻与描述整轮的字段；以触发本轮的提交为键做每轮一次的检查点；条目的 `data` 与 `model`；带 `model` 的条目为什么等边界 |

第 5、6、8 篇的实测数据来自 Tether 的 M0 实验（[`docs/m0-findings.md`](https://github.com/wanglei99999/tether/blob/m0-server/docs/m0-findings.md)），测试机是 2 核 2 GiB 的 Ubuntu 24.04，Docker 29。第 1 到 7 篇也同步在思源笔记的「Agent 基础设施」笔记本里。
